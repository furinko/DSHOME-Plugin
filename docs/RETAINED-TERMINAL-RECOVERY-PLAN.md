第二轮收到真实Host `terminal cleanup failed; surviving pid: 0`，旧现场保留并显示错误，未假报结束。随后测试先观察真实shell就绪输出再换代，第三轮通过；不能因此认证该宿主关闭失败根因或稳定性已修复。失败日志保留。生产连接/授权源和GUI仍未验。

以下保留最初设计与发现，作为实现前历史记录。

2026-10-30 源码核对发现：shared-entry 的 current() 将所有写入、创建、关闭绑定原连接 generation，安全拒绝旧现场借用新连接；但 RecoveryShelf 又拒绝释放 started 终端，因此活跃终端跨代后可能永久阻止旧现场回收。旧侧栏断流重连通过，不覆盖此整窗路径。

不能为恢复方便删除 generation 检查，也不能直接将旧现场改绑新 owner，或以关闭标签/取消订阅推断进程死亡。

## 拟实现的显式收尾接口

仅对保留现场已记录的确定终端身份提供显式关闭，不恢复写入、重启或调整权限：

1. 当前真实 workspace 必须与旧现场相同，当前 Session 必须为终端原始所有者。
2. 用当前 authority 捕获全新短期租约，真实 Host project 查询必须匹配旧 project.projectId；所有 await 后复查同一租约，服务替换/成员撤回/会话跳转使在途操作失效。
3. 人明确确认关闭后，向真实终端接口提交原 sessionId + terminalId，仅使用服务仍可用的 owner，不猜测新远端映射。
4. 使用既有 cleanup 记录 pending/failed/confirmed；响应丢失保持未知并允许同一身份幂等重试，不能从列表消失推断关闭。
5. 仅在成功回执且身份仍匹配时移除原面板内容；文档/便笺保持，旧 scene 不自动释放。无确认不能清空 started 标记。
6. 多所有者逐一操作，不能通过一个会话把别人终端全关；仍不提供跨代输入能力。

需要测试：真实活跃 PTY 断线/新代际、原输入拒绝且不重放、原所有者显式结束、B拒绝关A、project变化拒绝、A→B→A在途租约失效、回执丢失及幂等重试、没有自动释放草稿。此文是待实现设计，不是已验收能力。
